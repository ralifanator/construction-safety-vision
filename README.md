# Система контроля техники безопасности по видеопотоку

Проект реализует серверную систему, которая:

- анализирует изображения и видео на наличие средств индивидуальной защиты (каски, жилеты);
- в режиме реального времени обрабатывает видеопотоки с камер;
- фиксирует устойчивые нарушения, сохраняет кадры-доказательства и формирует отчёты.

---

# Технологический стек

- **Backend:** FastAPI (uvicorn)
- **БД:** PostgreSQL
- **Аналитика:** Ultralytics YOLO (детекция людей и СИЗ) + OpenCV
- **Очереди/воркеры:** фоновые Python-процессы (`stream_worker.py`, `run_stream_workers.py`)
- **Развёртывание:** Docker + Docker Compose
- **Видеопотоки:** RTSP/HTTP, RTSP-сервер mediamtx (`bluenviron/mediamtx`)

---

# Веб-интерфейс

В проект входит веб-интерфейс (HTML/JS), доступный через браузер, с тремя основными вкладками:

1. **Обработка изображений**
2. **Обработка видео**
3. **Работа с видеокамерами**
   - текущие кадры;
   - список камер;
   - отчёты о нарушениях.

```text
.
├─ main_server.py               # FastAPI-приложение (API + фронт)
├─ config.yaml                  # Общие настройки (пороги детекции, видео и т.д.)
├─ init.sql                     # Скрипт создания таблиц PostgreSQL
├─ requirements.txt             # Python-зависимости

├─ docker-compose.yml           # Описание сервисов
├─ static/
│   └─ index.html               # Веб-интерфейс
├─ core/
│   ├─ __init__.py
│   ├─ config_loader.py
│   ├─ db_config.py
│   ├─ db_pg.py                 # Работа с PostgreSQL
│   ├─ processing.py            # Обработка одного кадра
│   ├─ video_processing.py      # Анализ видеофайлов
│   ├─ video_overlay.py         # Генерация размеченного видео
│   └─ tasks_processing.py      # Фоновые задачи по видео
├─ cameras_processing/
│   ├─ cameras.yaml             # Описание камер
│   ├─ stream_worker.py         # Обработка потока одной камеры
```

## Создаваемые директории

В процессе работы создаются директории:

- `last_frames/` — последние обработанные кадры с камер;
- `violations_frames/` — кадры с зафиксированными нарушениями;
- `uploads/` — загруженные видео/изображения.

# 2. Требования

- Docker
- Docker Compose
- ОС: Windows / Linux / macOS

Для демонстрации работы с камерой:

- OBS Studio (или аналог) для захвата веб-камеры ноутбука и отправки потока в RTMP/RTSP-сервер.

## 3.1. Клонирование репозитория

```bash
git clone <URL_репозитория>
cd <папка_проекта>
```

Убедитесь, что в корне лежат файлы:

и каталоги:

- `core/`

---

## 3.2. Запуск сервисов

Собрать и запустить все контейнеры:

```bash
docker compose up --build
```

### При первом старте

- контейнер `db` поднимает PostgreSQL с БД `tb_control`;
- выполняется `init.sql`;
- контейнер `rtsp_server` запускает RTSP/RTMP-сервер mediamtx;
- контейнер `backend` запускает FastAPI + фронт на порту `8000`;
- контейнер `workers_manager` запускает воркеры обработки камер.

### Проверка контейнеров

```bash
docker ps
```

Должны быть как минимум:

- `csafety_db`
- `csafety_rtsp`
- `csafety_backend`
- `csafety_workers_manager`

# 4. Настройка и синхронизация камер

Список камер описывается в файле:

```text
cameras_processing/cameras.yaml
```

## Пример RTSP-камеры

```yaml
- id: rtsp_cam1
  name: "RTSP-камера через mediamtx"
  location: "Ноутбук (OBS → RTMP → RTSP)"
  type: camera
  connection_type: rtsp
  camera_url: "rtsp://rtsp_server:8554/cam1"
  is_active: true
```

## Синхронизация с БД

После изменения `cameras.yaml` выполните:

```bash
docker exec -it csafety_backend python cameras_processing/sync_cameras.py
```

Скрипт:

- читает `cameras.yaml`;
- создаёт/обновляет записи в таблице `video_sources`;
- обновляет параметры камер.

# 5. Запуск и тестирование обработки камеры через OBS

Для демонстрации можно использовать веб-камеру ноутбука через OBS + mediamtx.
В OBS необходимо добавить источник Камера, зайти в Файл->Настройки->Трансляция.
В поле Служба выбрать Настраиваемый. в поле сервер ввести строку `rtmp://localhost:1935/cam1`, применить и начать трансляцию в главном меню. 

---

## 5.1. RTSP-сервер mediamtx

Простейшая конфигурация `mediamtx.yml`:

```yaml
paths:
  cam1: {}
```

### RTSP-адреса

Внутри Docker:

```text
rtsp://rtsp_server:8554/cam1
```

На хосте:

```text
rtsp://localhost:8554/cam1
```

### Порты

- `8554` — RTSP
- `1935` — RTMP

---

## 5.2. Настройка OBS Studio

1. Установите OBS Studio.
2. Создайте сцену.
3. Добавьте источник:
   - **Video Capture Device**
   - выберите веб-камеру.
4. Откройте:
   - `Файл → Настройки → Трансляция → В поле Служба выберите Настраиваемый, в поле Сервер введите `
5. Укажите:
   - `Служба: Настраиваемый`
   - `Сервер: rtmp://localhost:1935/cam1`
6. Нажмите **Начать трансляцию** в главном окне.

### Проверка логов RTSP-сервера

```bash
docker logs csafety_rtsp
```

После подключения поток будет доступен:

```text
rtsp://localhost:8554/cam1
```

---

## 5.3. Подключение камеры в системе

Убедитесь, что в `cameras.yaml` указано:

```yaml
connection_type: rtsp
camera_url: "rtsp://rtsp_server:8554/cam1"
is_active: true
```

Синхронизируйте камеры:

```bash
docker exec -it csafety_backend python cameras_processing/sync_cameras.py
```

После этого воркеры начнут:

- читать RTSP-поток;
- анализировать кадры;
- сохранять кадры в `last_frames/`;
- сохранять нарушения в `violations_frames/`;
- записывать события в БД.

# 7. Настройка числа воркеров

Количество воркеров:

- берётся из переменной `STREAM_WORKERS`;
- либо автоматически определяется по числу активных камер.

## Пример docker-compose.yml

```yaml
workers_manager:
  environment:
    DB_HOST: "db"
    DB_PORT: "5432"
    DB_NAME: "tb_control"
    DB_USER: "tb_user"
    DB_PASSWORD: "tb_password"
    STREAM_WORKERS: "3"
```
